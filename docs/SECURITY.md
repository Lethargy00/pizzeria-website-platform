## Rules for every change

- Tenant input is validated with the shared Zod schemas; unknown keys are errors.
- No raw HTML from tenant content; Markdown through the allow-list sanitizer; URL schemes `https:`, `mailto:`, `tel:` only.
- CSP: no `unsafe-inline`, no `unsafe-eval`. New origins only through a platform adapter that a tenant enabled.
- No secrets in the repo. Each adapter ships a `.env.example`; real values live in hosting or GitHub environment secrets, scoped per tenant.
- No PII in logs, fixtures or test data. Demo data is fictional.
- Never weaken a control to make a test pass (PROMPT.md §10).

## Recommended repository setup (Q8.4)

Apply when the plan allows it (see `docs/HANDOFF.md`):

1. **Branch protection / ruleset on `main`:** require a pull request; require status checks `ci / guards`, `ci / build-test`, `pr-gates / review-gate`, `pr-gates / touches-guard`, `security / gitleaks`, `security / deps`; require branches to be up to date; block force-pushes and deletion; include administrators.
2. **Two-person review on `main`** for `packages/`, `.github/` and `scripts/` via CODEOWNERS (`.github/CODEOWNERS`).
3. **Per-role identities:** move from one shared account to one GitHub App per role (orchestrator, architect, security, …). Then `approved:<role>` labels can be replaced by real GitHub approvals, and `review-gate` can check the approver's identity. Until then approvals rest on signed comments and Orchestrator verification (residual risk T13).
4. **Private vulnerability reporting** enabled; **Dependabot alerts and security updates** enabled.
5. **Environments** `staging-<slug>` and `production-<slug>` with required reviewers for production, holding per-tenant secrets.

## Supply chain

- One lockfile at the root; CI installs with `--frozen-lockfile`.
- Every dependency change needs a `type:dependency` issue approved by `architect` and `security`, an exact version and an entry in `docs/DEPENDENCIES.md`.
- GitHub Actions: pin to full commit SHAs with a version comment (`uses: actions/checkout@<sha> # v4.x.y`). Open finding until done; Dependabot (`github-actions` ecosystem) then keeps SHAs current.
